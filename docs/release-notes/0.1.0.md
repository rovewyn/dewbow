# Dewbow 0.1.0

The first public release provides a local Codex conversation workspace through one `dewbow` executable, with a Rust daemon and embedded operator Web interface. This is an early development release; public behavior and local-state compatibility are not yet stable.

## Changes

- Initialize private local configuration, inspect native capabilities with `doctor`, and open authenticated Web with `web`. The daemon can run in the foreground or as a user background process.
- Discover native conversations, read bounded saved history, explicitly connect an existing conversation, and create managed conversations with frozen execution settings.
- Run Default and Plan turns, steer active turns, answer native questions, respond to single-request approvals, and interrupt execution. Per-conversation state updates preserve fast native completion, while durable request identities and conservative restart recovery prevent uncertain delivery from silently starting another turn.
- Use a conversation workspace that fills the browser, with session navigation, independent scrolling, an optional details panel, private tool output and diffs, and streamed session updates. Browser closure does not stop daemon execution.
- Protect local state with private POSIX permissions or protected Windows ACLs, reject links and reparse points, and keep browser authentication separate from persistent control credentials. Retained TypeScript private-file helpers tolerate slow Windows PowerShell startup while preserving mandatory permission checks.

## Upgrade requirements

- Install the independent Codex CLI 0.162.1 separately and retain its companion binaries and resources. Native credentials, conversations and working files remain owned by Codex. Dewbow's executable does not require Node.js, npm or Rust at runtime.
- Distribution targets are Linux x64 (`x86_64-unknown-linux-gnu`, built on Ubuntu 24.04), Windows x64 (`x86_64-pc-windows-msvc`, built on Windows 2025), and macOS Apple Silicon (`aarch64-apple-darwin`, built on macOS 15). Linux requires GNU libc. Other architectures and older operating systems have no release coverage.
- No Dewbow-owned state reset is required for a fresh installation. Earlier TypeScript management databases are not imported or migrated; when moving from those development builds, use a fresh Dewbow [state directory](../operations.md#state-directory) and preserve the old state. Never reset native Codex data as part of this transition.
- This is the first official release, so there is no preceding release to roll back to. Reusing this release's state with older development executables is unsupported. Stop the selected daemon and its owned native runtime before replacing an executable or backing up Dewbow state.
- Dewbow-owned management contracts remain `v1`. This initial release establishes the starting CLI, API, configuration and local-state behavior rather than a compatibility guarantee for earlier development builds.

## Known limitations

- Automated tests use synthetic native storage and runtime fixtures. Release package checks validate checksums, metadata, archive contents and the extracted executable's `--version` and `--help`; they do not establish real Codex acceptance on every target. Run `doctor` and confirm native requirements on the selected host before use.
- Windows execution requires a functioning sandbox permitted by native Codex policy. Dewbow does not disable sandbox boundaries or provision legacy sandbox accounts automatically. External runtime, Unix socket and writer-lock observations remain unavailable or unknown on Windows.
- All production listeners bind to loopback and browser operations use operator authority. Remote hosts, network routing, MCP, external agent management, team channels and DingTalk integration are not supported.
- Binary signing, macOS notarization, installers, self-update, system services and boot startup are not included. Release assets are archives with the executable, CLI instructions, source metadata and separate SHA-256 checksums.
- npm packages remain private; this release does not publish packages to npm or crates.io.
